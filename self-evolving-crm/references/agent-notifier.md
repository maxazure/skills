# 通知推送 — 详细规范

> Agent 角色：Notifier Agent
> 触发方式：Cron 定时任务 + 实时事件
> 输出通道：Telegram（主）/ 本地 Markdown 文件（备份）

---

## 角色定义

Notifier Agent 负责将 CRM 系统产出的所有信息格式化为易读的通知，通过 Telegram 推送给用户。它是 CRM 系统与用户之间的唯一交互界面，需要在"信息完整"和"不打扰"之间取得平衡。

---

## 三种通知类型

### 1. 每日摘要（Daily Digest）

```bash
# Cron 配置
openclaw cron add --name "crm-daily" --cron "0 8 * * *" \
  --tz "Pacific/Auckland" --session isolated \
  --message "生成 CRM 每日摘要并推送" --wake now
```

触发时间：每天 08:00（NZST）

### 2. 每周报告（Weekly Report）

```bash
# Cron 配置
openclaw cron add --name "crm-weekly" --cron "0 9 * * 1" \
  --tz "Pacific/Auckland" --session isolated \
  --message "生成本周 CRM 关系健康报告" --wake now
```

触发时间：每周一 09:00（NZST）

### 3. 实时告警（Real-time Alerts）

触发条件：其他 Agent 产出需要立即通知用户的内容。包括：
- 会前简报（Meeting Prep Agent 产出）
- 紧急待办逾期提醒
- 关系健康评分骤降告警（单日下降 > 20 分）

## Telegram 格式规范

### MarkdownV2 注意事项

```
需要转义的字符: _ * [ ] ( ) ~ ` > # + - = | { } . !
emoji 可直接使用，无需转义
消息长度上限: 4096 字符（超出需拆分）
```

### Emoji 使用规范

| 用途 | Emoji | 含义 |
|------|-------|------|
| 紧急/逾期 | 🔴 | 需要立即处理 |
| 今日跟进 | 📋 | 今天计划的跟进 |
| 新联系人 | 👤 | 新发现的联系人 |
| 关系预警 | ⚠️ | 健康评分下降 |
| 待确认 | ❓ | 需要用户决策 |
| 健康状态 | 🟢🟡🟠🔴 | 对应健康评分等级 |
| 趋势上升 | 📈 | 关系升温 |
| 趋势下降 | 📉 | 关系冷却 |
| 完成 | ✅ | 无待办/已完成 |
| 日报标题 | 🤝 | CRM 日报标识 |
| 周报标题 | 📊 | 周报标识 |
| 时钟 | ⏰ | 时间相关提醒 |

## 每日摘要模板

### 优先级排序规则

```
1. 🔴 逾期待办（overdue）— 最高优先
2. 📋 今日跟进（today's followups）
3. 👤 新联系人（new contacts, past 24h）
4. ⚠️ 关系预警（health alerts）
5. ❓ 待确认（pending merges, decisions）
```

### 完整模板

```
🤝 CRM 日报 | 2026-03-20（周五，NZST）

> 日期格式：`YYYY-MM-DD`（NZST），时间格式：`HH:MM`（24小时制，NZST）。
━━━━━━━━━━━━━━━━━━

🔴 紧急跟进（2）:
• 张三 — 需求文档今日截止 (72🟡)
  ↳ 你承诺 3/20 发送，建议今天优先处理
• 李总 — 合同确认已逾期 2 天 (45🟠)
  ↳ 3/18 截止，对方可能在等你回复
  /draft 李总

📋 今日跟进（1）:
• 王总 — 轻量问候 (58🟡 📉)
  ↳ 16 天未联系，关系正在冷却
  /draft 王总

👤 新联系人（1）:
• 赵明 (产品经理 @ XYZ科技)
  ↳ 来源: 昨日邮件往来

```

### 各区块最大条目数

| 区块 | 最大条目 | 超出处理 |
|------|----------|----------|
| 紧急跟进 | 5 | 显示前 5 条 + "还有 N 条，发送 /overdue 查看全部" |
| 今日跟进 | 5 | 显示前 5 条 + "还有 N 条，发送 /today 查看全部" |
| 新联系人 | 3 | 显示前 3 条 + "还有 N 人" |
| 关系预警 | 3 | 显示前 3 条 |
| 待确认 | 3 | 显示前 3 条 |

## Telegram 交互命令

### 命令列表

| 命令 | 功能 | 示例 |
|------|------|------|
| `/detail <联系人>` | 显示完整联系人档案 | `/detail 张三` |
| `/done <action_id>` | 标记待办已完成 | `/done act_001` |
| `/snooze <联系人> <天数>` | 延后跟进提醒 | `/snooze 王总 7` |
| `/merge_yes` | 确认联系人合并 | 回复合并建议后使用 |
| `/merge_no` | 拒绝联系人合并 | 回复合并建议后使用 |
| `/draft <联系人>` | 触发起草跟进消息 | `/draft 张三` |
| `/overdue` | 查看所有逾期待办 | `/overdue` |
| `/today` | 查看今日所有跟进 | `/today` |
| `/health` | 查看所有联系人健康评分 | `/health` |
| `/stats` | 查看 CRM 统计数据 | `/stats` |

### /detail 输出格式

```
👤 张三 | 技术总监 | ABC科技
━━━━━━━━━━━━━━━━━━
📧 zhangsan@company.com
🏷️ 客户, 技术决策者
📊 健康: 72🟡 (📉 冷却中)
📅 认识: 2025-11-15 (4个月)
🔄 互动: 23次 | 上次: 3月18日

💬 关系摘要:
Q1 重点客户，正在评估 SaaS 方案。
技术层面已认可，等待预算审批。

📋 未闭环事项:
  📌 [我] 发送需求文档 — 截止 3/20 ❗逾期
  📌 [张三] 确认预算 — 截止 3/25

📅 最近 3 次互动:
  3/18 邮件 — 讨论二期开发排期
  3/15 会议 — 技术架构选型讨论
  3/10 邮件 — 发送项目概述文档
```

### /done 处理逻辑

```
用户发送: /done act_001
系统处理:
  1. 在 contacts_db 中找到对应 action item
  2. 将 status 更新为 "completed"
  3. 记录完成时间
  4. 检查是否触发后续动作（如完成文档发送 → 更新 next_followup_date）
  5. 回复: "✅ 已完成: 发送需求文档给张三"
```

### /snooze 处理逻辑

```
用户发送: /snooze 王总 7
系统处理:
  1. 找到王总的联系人档案
  2. 将 next_followup_date 延后 7 天
  3. 记录 snooze 操作（用于分析用户跟进偏好）
  4. 回复: "⏰ 已延后: 王总的跟进提醒推迟到 3/27"
```

## 空摘要处理

当日所有区块均为空时，不发送空白摘要，而是发送简短确认：

```
✅ CRM 日报 | 2026-03-20

今日无紧急事项，无到期跟进。
当前活跃联系人: 87 人 | 平均健康: 64.2🟡

祝你有个高效的一天！
```

## 消息拆分策略

当内容超过 Telegram 4096 字符限制时：

```
拆分规则:
  1. 按区块拆分（每个区块一条消息）
  2. 第一条消息包含标题 + 紧急跟进 + 今日跟进
  3. 第二条消息包含新联系人 + 关系预警 + 待确认
  4. 如果单个区块就超限，按条目拆分
  5. 每条拆分消息标注 "(1/3)" 等序号

发送间隔: 每条消息间隔 500ms，避免 Telegram rate limit
```

## 故障回退机制

### Telegram 推送失败处理

```
重试策略:
  第 1 次失败: 等待 5 秒后重试
  第 2 次失败: 等待 30 秒后重试
  第 3 次失败: 放弃 Telegram，触发本地回退

本地回退:
  保存路径: ~/crm-reports/YYYY-MM-DD.md
  文件格式: 标准 Markdown（去掉 Telegram 格式限制）
  日志记录: 在 error_log 中记录失败原因和时间
```

### 本地备份文件格式

```markdown
# CRM 日报 | 2026-03-20

> Telegram 推送失败，本地备份
> 失败原因: Connection timeout
> 生成时间: 2026-03-20T08:00:15+13:00

## 紧急跟进

- **张三** — 需求文档今日截止 (健康: 72)
  - 你承诺 3/20 发送，建议今天优先处理
- **李总** — 合同确认已逾期 2 天 (健康: 45)
  - 3/18 截止，对方可能在等你回复

## 今日跟进

- **王总** — 轻量问候 (健康: 58, 趋势下降)
  - 16 天未联系，关系正在冷却

...（以下省略，结构与 Telegram 版一致）
```

### 备份文件清理

```
保留策略: 最近 90 天的本地备份
清理时机: 每周一周报生成前自动清理过期文件
```

## 通知频率控制

### 防骚扰规则

| 规则 | 说明 |
|------|------|
| 每日摘要 | 最多 1 条/天，固定 08:00 |
| 每周报告 | 最多 1 条/周，固定周一 09:00 |
| 会前简报 | 每个会议最多 1 条，会前 30 分钟 |
| 实时告警 | 每小时最多 3 条，超出合并到下一次每日摘要 |
| 用户命令回复 | 无限制（用户主动发起） |

### 免打扰时段

```yaml
quiet_hours:
  start: "22:00"
  end: "07:00"
  behavior: "queue"  # 在免打扰时段产生的通知排队到 08:00 统一推送
```
